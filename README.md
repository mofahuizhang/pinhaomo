## 五件的关系

不是系列，是**成套**。

| | 七族（另案） | 这五件 |
|---|---|---|
| 关系 | 系列：同一体例、同一内核、四域同构 | 成套：各管一段，靠引用纪律缝合 |
| 体例 | 七族同体 | 四种不同（营造法式／通典／律令格式／农书） |
| 互引 | 各族自足，"不引用其他著作" | 交叉密集，故须同批出 |

**引用纪律四条**：上游只声明接口，不定义下游内容；下游只引用编号，不复制上游定义；术语有歧义时以项目层术语表为准；跨项目的新机制先回归属项目立规，再于下游引用。

所以五件不追求"单篇自足"——那会立刻产生两份定义，日后一改就漂移。解法是让邻居同时可得：逐件登记（法律上各自独立），同批发布（工程上指针可解析）。

## 四部与副篇

正编四部，各立一体：

- **架构**＝《内核旋钮架构》，讲单主体内部怎么搭
- **协议**＝《MCP 控制层协议规范》，讲模块之间怎么连
- **主篇**＝《拼好模主篇》，讲多主体怎么治
- **园丁**＝《园丁计划》，讲系统怎么随时间演化

《拼好模副篇》是主篇的副篇，不入四部，记赛道测算与健康守护一例。

四部简称在五件正文中通用；术语若同名异义，以各件「附·术语总表」的分称为准（原语、候选、内核、判据、审计、四可，六词各有分称）。
